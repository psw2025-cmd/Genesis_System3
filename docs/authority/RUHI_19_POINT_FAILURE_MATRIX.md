## Hard acceptance law

For user-visible System3 claims, repository text, CI, workflow green, source code, or design output are never the final truth. Final truth is the current GCP-hosted dashboard and its same-session APIs, with exact serving SHA/revision, semantic content, freshness/source lineage, and API↔UI agreement. For trading automation, this includes real read-only broker/market truth and complete PAPER lifecycle evidence while LIVE/orders remain disabled.

## Required final fields for every material agent update

- `AGENT_OWNED_ACTION=` what the agent is doing now without asking the user.
- `MANDATORY_USER_ACTION=` `NONE` or the true human/account blocker.
- `OPTIONAL_ACCELERATION_ACTION=` `NONE` or the highest-gain user-side speedup.
- `LIVE_DASHBOARD_PROOF=` `PASS`, `FAIL`, or `UNPROVEN` with capture time and exact serving identity when applicable.
- `HIGHEST_GAIN_NEXT_ACTION=` one concrete next action, not a discussion topic.

No agent may claim final completion while `LIVE_DASHBOARD_PROOF=UNPROVEN` for a user-visible requirement.
